# パーツの3Dモデルの作り方と置き方

機体のパーツ（フレーム・武器・スキル）を、仮の箱から3Dモデルに置き換える手順。モデルがないパーツは今までどおり箱で描くので、1つずつ増やしていける。

読み込む処理は `view/arena/part_models.gd`、機体への組み付けは `view/arena/robot_view.gd`、大きさや質感の調整値は `view/look.gd` の「パーツの3Dモデル」にある。

## 今入っている仮のモデル

`assets/models/parts/` の20個（フレーム6・武器8・スキル6）は、`tools/make_placeholder_models.gd` が箱・円柱・三角柱などを組み合わせて作った仮のモデル。本番のモデルができたら、同じ名前で上書きすればよい。

- 作り直し（プロジェクト直下で）：`godot --headless --path . -s tools/make_placeholder_models.gd`。すべて上書きされるので、本番のモデルと入れ替えたあとは実行しない
- 汚れの模様（色むらとさびの斑点）は128pxの小さな画像に焼き込んである
- フレームには、枠の数だけ取り付け位置の目印（`weapon_0` など）が入っている

## 置き場所

`data/parts.json` の各パーツの `model` に書いた場所に、その名前で置く。

```
assets/models/parts/frame_tank.glb
assets/models/parts/weapon_spike.glb
...
```

- 形式は glTF のバイナリ（`.glb`）。Blender なら「ファイル → エクスポート → glTF 2.0」で「glTF バイナリ（.glb）」を選ぶ
- `.glb` や画像は Git LFS で管理される（`.gitattributes` に設定済み）。コミットの前に一度 `git lfs install` を実行しておく
- 置いてすぐ試すときは、Godot に取り込む前でもゲームがその場で読む。配布用に書き出す前には、Godot のエディタでプロジェクトを開くか `godot --headless --path . --import` を実行して取り込んでおく

## 向きと大きさ

| 決まり | 内容 |
| --- | --- |
| 前 | +X（Blender でも +X を前にして作る。glTF の書き出しの「+Y を上」は入れたままでよい。迷ったらゲームで見て直す） |
| 上 | +Y |
| 大きさ | 自動でそろえるので気にしなくてよい（`view/look.gd` の `MODEL_AUTO_FIT`）。フレームは前後・左右の長いほうが機体の当たり判定の直径に、武器・スキルは一番長い辺が決まった長さになる |
| 原点 | どこでもよい。フレームは底を床に、前後左右の真ん中を機体の中心に合わせて置く。武器は後ろの面を取り付け位置に当てて前へ伸ばす。スキルは底を取り付け位置に乗せる |

## 取り付け位置の目印（フレームだけ）

フレームのモデルの中に、空のオブジェクト（Blender の「エンプティ」）を置くと、そこに武器とスキルが付く。

- 名前は `weapon_0`、`weapon_1`、… と `skill_0`、`skill_1`、…（番号は0から。大文字小文字は区別しない）
- 武器の目印は、武器を前（+X）へ伸ばす向きにしておく。目印を回すと武器も回る
- 目印がない、または足りないときは、箱のときと同じ場所（武器は前に並べる、撃つ武器は上、スキルは後ろの上）に付く
- フレームの枠の数（`weapon_slots`・`skill_slots`）より多く置いても使われない

## 荒い質感を保つ

ゲームは3Dを1/3の解像度で描いて引き伸ばし、色の段数を減らし、ざらつきを重ねている（`view/look.gd` の `PIXEL_SHRINK` と `ARENA_POST`）。そのうえで、読み込んだモデルの材質を次のように直す。

- テクスチャをぼかさない（ドットの粗さが残る）
- つやを抑える（`MODEL_ROUGHNESS_MIN`）、金属らしさを抑える（`MODEL_METALLIC_MAX`）
- 陣営の色を少し混ぜる（`MODEL_SIDE_TINT`）。2機の見分けのため

モデルを作るときに気をつけること：

- ポリゴンは少なめ（数百〜数千）。細かい形は描いても潰れる
- テクスチャは小さめ（256〜512px）。大きくしても画面では見えない
- さび・傷・汚れのある、つやの少ない鉄の絵にする。全パーツで画風をそろえる
- 機体の形がひと目で分かる、はっきりした輪郭にする（上から斜めに見下ろす画面で、小さく映る）

## AIで作るとき（Tripo AI など）

企画メモの方針どおり、AIで下地を作り、人が仕上げる。

1. 元にする画像をそろえる：同じ画風・同じ角度（斜め前）・無地の背景。さびた鉄、つやなし、と指示する
2. 画像から3Dにして、低ポリゴン化とテクスチャの縮小をかけてから `.glb` で書き出す
3. Blender で向きを直し、汚れや機械部品を足し、フレームには取り付け位置の目印を置く
4. `assets/models/parts/` に置いてゲームで見る

**ライセンスに注意**：公開するゲームに入れるモデルは、そのサービスの規約で商用に使えるものだけにする。Tripo AI は無料プランで作ったものは商用に使えないとされている（2026年11月時点の情報。使う前に公式の料金・規約ページで確かめる）。試作は無料、本番用は有料プランで作り直す、のように分けるとよい。

## 確かめ方

- 自動テスト：`tests/test_part_models.gd`（テストの中で小さな `.glb` を作って、読み込み・目印・大きさ・材質・箱への戻りを確かめる）
- 見た目：ゲームを起動してバトルを見る。モデルが使われないときは、出力に「モデルを読めない」と出ていないか、`parts.json` の名前と合っているかを見る
